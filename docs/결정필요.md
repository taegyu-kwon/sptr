## 정한 것

### 1. ★ 처음 실제로 써 볼 팀
- **지금:** 예시 팀 "성남중학교 야구부" 하나. 팀을 만드는 화면 없음.
- **왜:** 실제 팀이 정해지면 그 팀의 운영 방식(누가 측정하나, 코치 몇 명)에 맞춰 흐름을 설계할 수 있다.
- **추천:** 아직 없다면 예시 팀으로 1~3단계를 진행하고, 4단계(시범 운영) 전까지만 정하면 된다. 다만 실제 팀이 있으면 그 팀 코치에게 지금 운영 방식을 먼저 들어 보는 게 1단계 흐름 설계에 가장 도움이 된다.
- **답 (2026-10-03):** 추천대로. 시범 운영은 예시 팀 하나로 시작하고, 실제 팀은 4단계 전까지 정한다.

### 2. ★ 여러 팀을 받을지
- **지금:** 팀 1개 고정.
- **왜:** 처음부터 여러 팀을 전제로 DB를 짜야 나중에 갈아엎지 않는다. 팀 개설을 누가 하는지도 함께 정한다.
- **선택지:** 한 팀 시범 후 확장 / 처음부터 여러 팀
- **추천:** DB는 여러 팀 구조로 만들고, 팀 개설은 당분간 태규님이 직접.
- **답 (2026-10-03):** 추천대로. DB는 여러 팀 구조. **관리자(태규님) 역할을 새로 두고**, 팀이 처음 들어올 때 관리자가 관리자 계정으로 팀을 직접 만들고 팀 설정(이름 등)을 고친다. 코치는 팀을 만들 수 없다.

### 3. ★ 측정값을 누가 입력하나
- **지금:** 신체·운동능력·실전·SBI 측정값은 선수(학부모) 계정만 입력한다. 코치 확인 없이 점수·순위·추천 라인업에 바로 반영. 코치는 입력할 수 없다.
- **왜:** 선수 입력은 값을 부풀릴 수 있고, 코치 입력은 코치 일이 늘어난다. 화면·권한·DB가 모두 달라진다.
- **선택지:** 선수 입력 / 코치·트레이너만 입력 / 선수 입력 + 코치 승인 후 반영
- **추천:** 선수 입력 + 코치 승인 후 반영, 코치는 직접 입력도 가능. 선수가 넣은 값은 "확인 대기"로 본인에게만 보이고, 코치가 확인하면 점수·순위·추천 라인업에 들어간다. 팀 단체 측정 날에는 코치가 한꺼번에 입력한다.
- **답 (2026-10-03):** 측정 항목 34개(신체·운동능력·실전·SBI/SMI) 모두 감독·코치가 입력한다. 선수·학부모는 입력하지 않고 보기만 한다. 코치가 넣으므로 확인 단계는 두지 않는다.
- **구현 (2026-11-21, 로컬):** 코치가 선수 상세에서 측정 기록을, SBI/SMI 상세에서 SBI 측정값을 입력한다. 선수·학부모 화면은 보기 전용.

### 4. ★ 코치 계정 구성
- **지금:** 코치 가입 코드는 예시 1개뿐이고 앱에서 발급할 수 없다. 코치끼리 권한 구분 없음.
- **정할 것:** 팀당 코치 몇 명, 감독·코치 권한을 나눌지, 누가 코치를 초대하나.
- **추천:** 팀당 코치 여러 명, 권한은 두 단계. 감독은 팀 관리(선수 등록·삭제, 코치 초대 코드 발급)까지, 코치는 기록·피드백·라인업까지. 첫 감독 계정은 팀을 만들 때 태규님이 발급한다.
- **답 (2026-10-03):** 추천대로. 코치는 팀당 여러 명, 권한은 감독·코치 두 단계. 관리자가 팀을 만들며 감독 코드를 발급하고, 감독이 자기 팀 코치 코드를 발급한다. 선수 삭제처럼 되돌릴 수 없는 일은 감독만.

### 5. ★ 학부모 계정
- **지금:** 선수와 학부모가 계정 하나를 함께 쓴다(가입 코드가 선수당 1개, 1회용).
- **선택지:** 공유 유지 / 학부모 계정 따로 — 따로 두면 볼 수 있는 범위와 입력 권한도 정한다
- **추천:** DB는 처음부터 "선수 한 명에 계정 여러 개(본인·학부모)"가 붙을 수 있게 만들고, 시범 운영 동안은 화면을 하나로 공유한다. 학부모 전용 화면·권한은 시범 운영 피드백을 보고 정한다.
- **답 (2026-10-03):** 선수 1명당 계정 2개 — 선수 본인 계정 1개 + 학부모 계정 1개(부모가 함께 사용). 가입 코드는 본인용·학부모용을 따로 발급한다. 학부모 화면은 시범 운영 동안 선수 화면과 같게 둔다.
- **구현 (2026-11-21, 로컬):** 본인·학부모 코드를 따로 발급하고 학부모 코드로 가입하면 그 선수의 화면을 본다. 학부모는 출석 체크·신고를 하지 않는다.

### 6. 본인인증
- **지금:** 버튼을 누르면 확인 없이 완료된다(가짜).
- **선택지:** 실제 휴대폰 본인인증(유료 외부 서비스, 건당 비용) / 빼고 가입 코드만으로 가입 / 이메일 인증만
- **추천:** 시범 운영까지는 가입 코드 + 이메일 인증.
- **답 (2026-10-03):** 가입 코드 + 이메일 인증. 가입할 때 이메일로 온 링크를 눌러 확인하고, 비밀번호 찾기도 이메일로 한다. 휴대폰 본인인증은 쓰지 않는다.
- **구현 (2026-11-21, 로컬):** 가짜 휴대폰 본인인증 버튼을 없앴다. 이메일 인증·비밀번호 찾기는 서버 연결(2단계 5)에서.

### 7. 가입 코드 정책
- **지금:** 1회용, 만료 없음. 순번(SPTR-PLAYER-03, 04…)이라 다음 코드를 짐작할 수 있다. 선수를 이름으로 연결한다.
- **정할 것:** 만료 기간, 재발급 허용 여부.
- **추천:** 코드는 무작위 문자로, 선수 연결은 이름이 아니라 선수 자체로(2단계에서 처리).
- **답 (2026-10-03):** 무작위 코드, 14일 안에 가입하지 않으면 만료, 감독(선수·코치 코드)·관리자(감독 코드)가 재발급할 수 있다. 선수 연결은 이름이 아니라 선수 자체로 한다.
- **구현 (2026-11-21, 로컬):** 무작위 `SPTR-XXXX-XXXX`, 발급 후 14일·1회용, 재발급 시 이전 코드 폐기, 선수 id로 연결. 감독·관리자 구분이 아직 없어 코치 계정이면 누구나 발급한다.

### 13. ★ 선수 삭제 시 지난 기록
- **지금:** 선수를 지우면 지난 경기의 타격·투구 기록도 함께 지워져 팀 누적 기록이 바뀐다.
- **선택지:** 지금처럼 삭제 / 졸업·이적으로 처리해 기록은 보관하고 목록에서만 숨김
- **추천:** 보관.
- **답 (2026-10-03):** 보관 처리. 선수를 졸업·이적으로 표시해 목록에서만 숨기고, 지난 경기의 타격·투구 기록과 팀 누적 기록은 남긴다.
- **구현 (2026-11-21, 로컬):** 선수 삭제를 없애고 보관(졸업·이적·기타)·복원으로 바꿨다.

### 15. 투구 이닝 표기
- **지금:** 이닝을 소수로 입력·합산해 5⅓이닝을 "5.1"로 쓰면 5.1이닝으로 계산되어 ERA가 틀어진다.
- **답 (2026-10-03):** 야구 관례대로 ⅓ 단위. 5.1 = 5⅓이닝, 5.2 = 5⅔이닝으로 받고 서버에는 아웃 수로 저장한다. 소수 첫째 자리가 3 이상이면 입력 오류.

### 16. ★ 선수 본인 계정의 이메일

### 17. ★ 형제의 학부모 계정

### 18. ★ 보관된 선수의 로그인
- **지금:** 졸업·이적으로 보관된 선수(결정 13)의 계정을 어떻게 할지 정해지지 않았다.
- **답 (2026-10-03):** 로그인 불가. 보관되면 선수 본인 계정은 잠긴다. 학부모 계정은 연결된 자녀가 모두 보관되면 잠기고, 활동 중인 형제가 있으면 그 자녀만 보인다.
- **구현 (2026-11-21, 로컬):** 보관된 선수의 본인·학부모 계정은 로그인이 거부된다(형제 연결이 없어 학부모 계정도 함께 막힘).

### 19. ★ 관리자의 팀 데이터 열람
- **지금:** 관리자는 팀을 만들고 설정한다(결정 2). 팀 안의 선수·기록을 볼 수 있는지는 정해지지 않았다.
- **답 (2026-10-03):** 읽기 전용으로 모든 팀을 볼 수 있다(문의 대응용). 입력·수정은 감독·코치만.

### 20. ★ 서버(Supabase) 프로젝트
- **지금:** sptr는 서버가 없다. 태규님은 sportir·출타·political에서 Supabase 프로젝트 3개를 쓰고 있다.
- **답 (2026-10-03):** sptr 전용 프로젝트를 새로 만든다. 태규님은 Supabase 유료 구독 중이라 프로젝트 수 제한·일시 정지 걱정은 없다. 추가 비용은 만들 때 대시보드에서 확인한다. sportir DB에 같이 넣지 않는다(운영 중인 DB의 권한 정책과 섞일 위험).

### 21. 가입·비밀번호 메일 발송
- **지금:** Supabase 기본 메일은 팀원 주소로만 보내져 실제 가입에 쓸 수 없다.
- **답 (2026-10-03):** sptr 전용 도메인을 사서 Resend(월 3,000통 무료)로 보낸다. 같은 도메인을 앱 주소로도 쓸 수 있다. **도메인 이름과 구입은 보류** — 2단계 1(Supabase 준비) 전에 정한다. 조회 시 비어 있던 후보: sptr.co.kr, getsptr.com, sptrapp.com(구입 사이트에서 최종 확인 필요).

### 22. ★ 야구부장 역할
- **지금:** 역할은 관리자·감독·코치·선수·학부모 다섯이었다. 학교 야구부에는 담당 선생님인 야구부장이 있다.
- **답 (2026-10-03):** 야구부장 역할을 새로 둔다. 팀당 1명, 관리자가 팀을 만들 때 감독 코드와 함께 야구부장 코드를 발급한다. 권한은 팀 관리(가입 코드 발급·재발급·보기, 선수 등록·보관, 코치 초대)와 모든 화면 보기. 측정·기록 입력, 피드백, 훈련 일정, 라인업은 감독·코치가 한다. **가입 코드는 감독과 야구부장만** 보고 발급한다(코치는 못 봄).

### 24. 출석 상태와 출석률
- **지금:** 출석 화면(2026-11-05)을 만들며 상태와 출석률 공식을 임시로 정했다. 사유결석이 분모에 들어가 재활 선수의 출석률이 낮게 나왔다.
- **답 (2026-11-05):** 상태는 출석·지각·결석·사유결석 4가지. 출석률 = (출석 + 지각) ÷ (기록한 날 − 사유결석) — 사유결석은 분모에서 뺀다. 분모가 0이면 "-".
- **답 (2026-11-05 추가):** 출석은 **선수 본인이 자기 계정에서 직접 체크**한다(오늘만, 늦어요/못 가요 신고 포함). 코치는 현황을 보고 잘못된 기록만 고친다.
- **남은 것:** 체크 가능 시간 제한·지각 자동 판정·미체크 처리는 27번으로 옮김.

### 25. 팀을 배명고등학교로
- **지금:** 예시 팀이 "성남중학교 야구부"(중학교)였다. 선수 나이·상대팀·대회 이름도 중학교 기준이었다.
- **답 (2026-11-21):** 앱의 팀을 **배명고등학교 야구부**(서울 송파)로 한다. 예시 선수 나이는 16~18세, 예시 상대팀·대회는 서울권 고교 기준으로 바꾼다. 선수 명단과 기록은 아직 예시 데이터다. 점수 기준·SBI가 U15(중학) 그대로인 것은 26번에서 정한다.
