## 운영 방식

### 1. ★ 처음 실제로 써 볼 팀
- **지금:** 예시 팀 "성남중학교 야구부" 하나. 팀을 만드는 화면 없음.
- **왜:** 실제 팀이 정해지면 그 팀의 운영 방식(누가 측정하나, 코치 몇 명)에 맞춰 흐름을 설계할 수 있다.
- **답:**

### 2. ★ 여러 팀을 받을지
- **지금:** 팀 1개 고정.
- **왜:** 처음부터 여러 팀을 전제로 DB를 짜야 나중에 갈아엎지 않는다. 팀 개설을 누가 하는지도 함께 정한다.
- **선택지:** 한 팀 시범 후 확장 / 처음부터 여러 팀
- **추천:** DB는 여러 팀 구조로 만들고, 팀 개설은 당분간 태규님이 직접.
- **답:**

### 3. ★ 측정값을 누가 입력하나
- **지금:** 신체·운동능력·실전·SBI 측정값은 선수(학부모) 계정만 입력한다. 코치 확인 없이 점수·순위·추천 라인업에 바로 반영. 코치는 입력할 수 없다.
- **왜:** 선수 입력은 값을 부풀릴 수 있고, 코치 입력은 코치 일이 늘어난다. 화면·권한·DB가 모두 달라진다.
- **선택지:** 선수 입력 / 코치·트레이너만 입력 / 선수 입력 + 코치 승인 후 반영
- **답:**

### 4. ★ 코치 계정 구성
- **지금:** 코치 가입 코드는 예시 1개뿐이고 앱에서 발급할 수 없다. 코치끼리 권한 구분 없음.
- **정할 것:** 팀당 코치 몇 명, 감독·코치 권한을 나눌지, 누가 코치를 초대하나.
- **답:**

### 5. ★ 학부모 계정
- **지금:** 선수와 학부모가 계정 하나를 함께 쓴다(가입 코드가 선수당 1개, 1회용).
- **선택지:** 공유 유지 / 학부모 계정 따로 — 따로 두면 볼 수 있는 범위와 입력 권한도 정한다
- **답:**

### 6. 본인인증
- **지금:** 버튼을 누르면 확인 없이 완료된다(가짜).
- **선택지:** 실제 휴대폰 본인인증(유료 외부 서비스, 건당 비용) / 빼고 가입 코드만으로 가입 / 이메일 인증만
- **추천:** 시범 운영까지는 가입 코드 + 이메일 인증.
- **답:**

### 7. 가입 코드 정책

- **추천:** 코드는 무작위 문자로, 선수 연결은 이름이 아니라 선수 자체로(2단계에서 처리).

## 점수 · 평가 (앱의 핵심)

### 8. 계산 기준의 근거
- **지금:** 등급 구간, 세부 지표 기준값 23개, 부상 리스크 가중치, SBI의 C=5.1과 환산 구간 모두 출처가 적혀 있지 않다. 중1과 중3이 같은 기준으로 채점된다. 전체 목록은 `계산기준.md`.
- **정할 것:** 어떤 자료를 기준으로 삼나, 화면에 출처를 밝힐지, 학년별 기준을 나눌지.
- **답:**

### 9. "부상 리스크" 표현
- **지금:** 의학적 근거 표기 없이 "부상위험 높음/보통/낮음"을 선수·학부모에게 보여준다.
- **정할 것:** 이 표현을 계속 쓸지(예: "관리 필요 신호"처럼 바꿀지), 선수·학부모에게도 보여줄지.
- **답:**

### 10. 팀 내 순위 공개 범위
- **지금:** 선수·학부모가 팀 전원의 이름과 종합·운동능력·실전 점수를 본다. 신체 점수만 숨기지만 종합 점수로 역산된다.
- **선택지:** 지금처럼 전체 공개 / 내 순위만 / 상위 몇 명만 / 다른 선수 이름 가리기
- **답:**

### 11. 실측 전 신규 선수
- **지금:** 코치가 선수를 등록하면 나이·키·몸무게 외 항목을 평균 기본값으로 채워 점수·순위·추천 라인업·부상 리스크에 바로 들어간다. 예: 플랭크 기본값 60초 때문에 측정 전부터 "코어 안정성 부족"이 붙는다.
- **선택지:** 유지 / 실측 전에는 점수를 "측정 전"으로 숨기고 순위·추천에서 제외
- **추천:** 숨기고 제외.
- **답:**

### 12. SBI 코치 화면의 신장·구속
- **지금:** 계산기는 입력한 신장·구속으로 계산하지만, 저장 후 코치 화면은 측정 기록의 최신값으로 다시 계산해 점수가 다를 수 있다. 야수는 "최고 구속" 자리에 송구 속도가 들어간다.
- **정할 것:** 어느 값을 기준으로 할지, 야수의 SBI를 어떻게 계산할지.
