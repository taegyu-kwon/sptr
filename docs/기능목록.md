# 기능 목록서

SPTR 앱이 **지금 실제로 무엇을 하고 무엇을 못 하는지**를 한 줄씩 적은 문서.
기능을 바꿀 때마다 해당 줄의 상태와 "바뀐 날"을 함께 고친다. 왜 바꿨는지는 `변경기록.md`에 적는다.

기준일: 2026-11-22 · 화면 24개(+ 공통 영역 2개: 상단 헤더·탭 메뉴 · 역할별 화면 이동) · 동작 184줄 · 모드 2개(서버 / 체험)

## 요약

| 상태 | 줄 수 | 뜻 |
|---|---|---|
| 실제 동작 | 164 | 입력하면 저장되고 다른 화면에 반영된다 / 보여주는 데이터를 앱 안의 누군가가 입력할 수 있다 |
| 예시 데이터 | 3 | 화면은 있지만 보여주는 데이터를 앱 안 어디에서도 입력할 수 없다 |
| 가짜 | 2 | 동작하는 척만 한다. 데모 편의 기능 포함(출시 전 제거) |
| 없음 | 15 | 필요한데 화면에 없다 |

> **가장 중요한 한계(서버 모드):** 이메일 확인이 꺼져 있어 아무 이메일로나 가입되고, 비밀번호를 잊으면 되찾을 방법이 없다. 가입한 누구나 "새 팀 시작"으로 팀을 만들 수 있고(관리자 전용 아님), 감독·코치 권한 구분이 없다. 다른 기기의 변경은 실시간이 아니라 창에 다시 들어오거나 60초마다 다시 읽을 때 반영된다. 체험 모드의 데이터는 여전히 **이 브라우저에만** 저장된다.

## 두 가지 모드 (2026-11-22)

| | 서버 모드 | 체험 모드 |
|---|---|---|
| 들어가는 법 | 로그인 화면에서 이메일·비밀번호 로그인 / 가입 코드로 회원가입 / 새 팀 시작 | 로그인 화면의 "코치로 체험하기 / 선수로 체험하기" |
| 저장 위치 | 서버(Supabase). 브라우저에는 로그인 토큰만 남는다 | 이 브라우저(localStorage). 서버를 호출하지 않는다 |
| 다른 기기와 공유 | 됨 — 코치가 입력한 것이 선수·학부모 기기에 보이고, 선수의 출석 체크·공지 읽음이 코치 화면에 보인다 | 안 됨 |
| 데이터 | 내 팀 것만. 권한 밖의 행은 서버(RLS)가 내려 주지 않는다 | 예시 팀 1개(배명중학교 야구부) |
| 로그인 유지 | 새로고침·탭을 닫아도 유지 | 탭 단위(탭을 닫으면 로그아웃) |
| 화면 표시 | 없음 | 화면 위에 "체험 모드 · 이 브라우저에만 저장" 배지 |

- 화면과 메뉴는 두 모드가 같다. 서버 모드는 로그인할 때 내 팀 데이터를 전부 읽어 화면에 쓰고, 저장하면 화면을 먼저 고친 뒤 같은 변경을 서버에 쓴다. 서버 쓰기가 실패하면 화면을 되돌리고 오류 알림("방금 변경한 내용은 되돌렸습니다")을 띄운 뒤 서버에서 다시 읽는다. 실패한 저장 뒤에 줄 서 있던 저장도 서버에 보내지 않고 화면에서 함께 되돌린다.
- 다른 기기의 변경은 창에 다시 포커스가 오거나 60초마다 팀 데이터를 다시 읽어 반영한다(실시간 아님). 다시 읽는 도중에 저장하면 그 저장이 끝난 뒤 한 번 더 읽는다.
- 선수 정보는 바뀐 칸만 서버에 보낸다 — 한 코치가 SBI 측정을 넣는 사이 다른 코치가 옛 화면에서 같은 선수의 특이사항·등번호를 고쳐도 서로 지우지 않는다. 한 칸 안의 목록(같은 선수의 SBI 이력, 같은 달 훈련 방향 목표, 같은 날 공지 시간표, 같은 라인업)을 두 기기가 함께 고치면 나중에 저장한 쪽이 남는다.
- 서버 모드에서 달라지는 것: 같은 선수·같은 날짜의 측정 기록은 1건, 선수·학부모 계정에는 가입 코드와 다른 사람의 계정 정보·공개 전 라인업·다른 선수의 개인 피드백이 내려오지 않는다, 옛 훈련표(`training`·`events`)는 없다.
- 서버 테이블·권한·함수는 `supabase/CONTRACT.md`가 기준.

- 바뀐 날: `MVP` = 7월 제작본 그대로, 날짜 = 그날 동작이 생기거나 바뀜(디자인·문구만 바뀐 건 제외).
- 저장 위치 "서버 / 브라우저" = 서버 모드에서는 **서버**(Supabase), 체험 모드에서는 **이 브라우저**(localStorage). 체험 모드의 메인 데이터는 `sptr-db-v6`, 훈련 공지·월간 일정은 `sptr-schedule-v4`, 로그인 상태는 탭 단위(sessionStorage `sptr-session-v1`). 키 버전이 올라가면 이전 저장본은 읽지 않고 예시 데이터로 새로 시작한다. 서버 모드 데이터는 브라우저에 저장하지 않는다.
- 점수·등급·리스크가 무엇으로 계산되는지는 `계산기준.md`, 제품 주인이 정해야 할 것은 `결정필요.md`.

## 데이터 현황

앱이 저장하는 데이터와 각각을 누가 만들고 고칠 수 있는지. 이름은 앱 안의 데이터 이름이다. 서버 모드에서는 Supabase 테이블 14개에 나뉘어 저장되고(대응은 `supabase/CONTRACT.md` 1절 — users → `profiles` + Supabase Auth, players.records → `measurements`, codes → `signup_codes`, schedule.notices → `notices` + `notice_reads`, schedule.games → `scheduled_games`), 누가 고칠 수 있는지는 서버 권한(RLS)이 한 번 더 막는다. `training`·`events`·`centers`는 서버에 없다. 비고의 "예시"는 체험 모드와 "예시 데이터로 시작"한 서버 팀에 들어가는 내용이다.

## 알려진 문제

고치지 않고 남겨 둔 문제와 언제 해결할지. 해결하면 줄을 지우고 `변경기록.md`에 남긴다.

| 문제 | 영향 | 해결 시점 |
|---|---|---|
| 이메일 확인이 꺼져 있음(서버 모드) | 아무 이메일로나 가입됨. 남의 이메일·없는 이메일로 만든 계정을 막지 못함 | 보내는 도메인·메일 발송 서비스가 생기면(결정필요 29) |
| 비밀번호 찾기 없음 | 비밀번호를 잊으면 그 계정을 다시 쓸 수 없음. 계정 연결 해제도 없어 같은 선수의 계정을 새로 만들 수도 없음 | 메일 발송과 함께 |
| 가입한 누구나 팀을 만들 수 있음(서버 모드) | "새 팀 시작"이 관리자 전용이 아니라 모르는 사람도 팀을 만들 수 있음. 다른 팀 데이터는 보이지 않음 | 결정필요 28(관리자만으로 좁히기) |
| 감독·코치 권한 구분 없음 | 코치 계정이면 누구나 가입 코드 발급·선수 보관·팀 정보 수정 가능(결정 4·22와 다름). 서버 권한도 코치·선수 본인·학부모 세 가지뿐 | 2단계(역할 6개) |
| 다른 기기의 변경이 실시간이 아님(서버 모드) | 창에 다시 들어오거나 60초마다 다시 읽을 때 반영. 코치가 선수 이름을 고쳐도 선수 화면에는 그때까지 예전 이름. 두 기기가 같은 항목(같은 경기·피드백·라인업, 같은 달 훈련 방향, 같은 날 공지, 같은 선수의 SBI 이력)을 함께 고치면 나중에 저장한 쪽이 남음. 선수 정보만 바뀐 칸 단위로 저장해 서로 다른 칸은 지우지 않음 | 미정 |
| 연결이 끊기면 저장되지 않음(서버 모드) | 서버 쓰기가 실패하면 화면을 되돌리고(뒤에 줄 선 저장 포함) 오류 알림을 띄움. 오프라인 저장·나중에 다시 보내기는 없음 | 미정 |
| 팀 없는 계정이 서버에 남을 수 있음 | 가입 도중 코드 사용·팀 만들기가 실패하면 로그인 계정만 생김. 다음 로그인에서 "팀에 가입해 주세요" 화면으로 이어 가지만, 계정을 지우는 방법은 없음 | 회원 탈퇴와 함께 |
| 역할별 데이터 구분이 일부만 서버에서 됨 | 서버 모드: 가입 코드·다른 사람 계정·공개 전 라인업·다른 선수의 개인 피드백은 선수 기기에 오지 않음. 팀 전체 측정 기록은 여전히 선수 기기에 옴("신체 등급 비공개"도 종합 점수로 역산 가능). 체험 모드는 화면에서만 구분 | 2단계 9(서버 점수) + 결정필요 10 |
| 체험 모드: 데이터가 이 브라우저에만 저장됨 | 체험 모드에서 입력한 것은 다른 기기·다른 브라우저에 없음. 비밀번호가 평문으로 저장되고, 로그인 상태가 사용자 id 문자열 하나라 저장값을 바꾸면 다른 예시 계정으로 들어가짐. 같은 브라우저의 여러 탭은 서로 덮어씀 | 2단계 10(데모 기능·브라우저 저장 제거) |
| 체험 모드: 저장 키 버전이 오르면 이전 데이터를 읽지 않음 | `sptr-db-v6`·`sptr-schedule-v4` 이전에 브라우저에 넣은 데이터는 보이지 않고 예시 데이터로 새로 시작 | 2단계 10 |
| 예시 데이터 날짜가 만든 날 기준으로 고정됨 | 체험 모드는 처음 열거나 "데모 데이터 초기화"를 누른 날, 서버 팀은 예시를 올린 날을 기준으로 만들어 저장하므로 며칠 뒤에는 그만큼 지난 날짜로 보임 | 2단계 10(예시 데이터 제거) |
