# 사용 흐름

로드맵 1단계 문서. 역할별로 **처음 들어오는 순간부터 한 시즌을 쓰는 동안 실제로 하는 일**을 순서대로 적고, 지금 앱으로 되는 것과 막히는 곳을 표시한다.
전제는 `결정필요.md`의 "정한 것"(1~7·13·15~22·24·25번). 남은 결정(8~12·14·23·26·27)은 정하지 않고 자리만 표시한다.

기준일: 2026-10-03 · "지금 상태" 칸 갱신: 2026-11-21(로컬 구현 반영) · 참고: `기능목록.md`(화면 이름·지금 상태), `결정필요.md`, `측정항목.md`

## 1. 한 줄 요약

관리자가 팀을 만들어 감독·야구부장을 들이고, 감독·야구부장이 코치·선수·학부모를 가입 코드로 들인 뒤, 코치진이 측정·훈련·시합·피드백을 기록하면 선수와 학부모가 같은 화면으로 성장과 일정을 본다.

| 역할 | 누가 | 할 수 있는 일 | 가입 방법 |
|---|---|---|---|
| 관리자 | 제품 주인 1명(태규님) | 팀 만들기, 팀 설정(이름·지역) 수정, 감독·야구부장 코드 발급·재발급 | 가입 코드 없음 — 서버에서 직접 만듦(가정 1) |
| 감독 | 팀당 1명(가정 2) | 선수 등록·보관, 선수·학부모 코드 발급·재발급, 코치 코드 발급·재발급 + 코치 일 전부 | 관리자가 준 감독 코드 + 이메일 인증 |
| 야구부장 | 학교 담당 선생님, 팀당 1명(결정 22) | 선수 등록·보관, 선수·학부모 코드 발급·재발급·보기, 코치 코드 발급·재발급 + 모든 화면 보기. 측정·기록 입력, 피드백, 훈련 일정, 라인업은 하지 않음 | 관리자가 준 야구부장 코드 + 이메일 인증 |
| 코치 | 팀당 여러 명 | 측정 기록(결정 3), 피드백, 주간 훈련·일정, 라인업, 시합 기록. 가입 코드는 볼 수 없음 | 감독 또는 야구부장이 준 코치 코드 + 이메일 인증 |
| 선수 | 선수 본인 | 자기 능력치·측정 기록·성장·순위·피드백·일정·라인업 보기, 출석 체크. 측정값은 입력하지 않음(결정 3) | 감독 또는 야구부장이 준 본인용 코드 + 이메일 인증 |
| 학부모 | 선수 1명당 계정 1개(부모가 함께 사용) | 시범 운영 동안 선수와 같은 화면을 보기 전용으로(출석 체크·신고는 선수 본인만) | 감독 또는 야구부장이 준 학부모용 코드 + 이메일 인증 |

## 2. 역할별 여정

읽는 법
- **화면:** `기능목록.md`의 화면 이름, 또는 `새 화면: ○○`. `앱 밖`은 문자·메신저·종이 등 앱 바깥에서 일어나는 일.
- **지금 상태:** 실제 동작 / 예시 데이터 / 가짜 / 없음 / 일부(있지만 이 흐름에 부족).
- **⟨코치 입력⟩:** 결정 3 확정(2026-10-03)으로 측정은 감독·코치만 입력한다. ⟨선수 입력⟩·⟨코치 확인⟩ 자리는 없어졌고, 앱에도 2026-11-21에 반영됐다(선수 상세 › 측정 기록, SBI/SMI 상세).
- **감독 또는 야구부장:** 둘 중 누가 해도 되는 팀 관리 단계(결정 22). 감독 여정과 야구부장 여정에 같은 단계로 함께 적는다.
- **공통 전제:** "실제 동작"도 지금은 **이 브라우저 안에서만** 동작한다. 한 사람이 만든 것을 다른 사람이 다른 기기에서 이어받는 단계(코드 → 가입, 기록 → 선수 화면)는 모두 2단계(서버 연결)가 있어야 실제로 이어진다. "실제 동작(로컬)"은 2026-11-21에 화면과 동작을 만들었지만 감독·야구부장 권한 구분 없이 코치 계정이면 누구나 쓰는 상태를 뜻한다.
