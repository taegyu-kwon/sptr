# 로드맵

SPTR을 예시 데이터 앱에서 실제 팀이 쓰는 앱으로 만드는 순서. 단계마다 끝나는 기준이 있고, 기준을 태규님이 확인해야 다음 단계로 넘어간다.

## 2단계 — 서버 연결
`DB설계.md` 9장의 12단위. 4단위(예시 데이터 넣기)까지는 운영 주소에 지금 앱을 그대로 두고 미리보기 주소로 확인한다.

| # | 단위 |
|---|---|
| 1 | Supabase 프로젝트·메일 발송·메일 문구·앱 연결 |
| 2 | 테이블 18개와 값 검사 |
| 3 | 권한(RLS)·가입 코드 함수 + 되돌리기 SQL |
| 4 | 예시 팀 데이터 넣기 |
| 5 | 로그인·가입·이메일 확인·비밀번호 찾기 화면 |
| 6 | 가입 코드: 관리자 팀 만들기·감독 코드, 감독 코치 코드, 선수 본인·학부모 코드 |
| 7 | 모든 화면이 서버에서 읽기 |
| 8 | 모든 입력이 서버에 저장 |
| 9 | 비교되는 점수(종합·분야·SBI·SMI)를 서버에서 계산 |
| 10 | 데모 기능·브라우저 저장 제거 |
| 11 | 역할 5개로 권한 점검 |
| 12 | 문서 갱신 |

**끝나는 기준:** 코치가 노트북에서 입력한 것이 선수 휴대폰에 보이고, 역할별 권한 점검이 설계와 일치.

## 3단계 — 빠진 화면 채우기
`사용흐름.md` 3·4장 기준.

**시범 운영에 필수**
- [ ] 팀 관리(관리자): 팀 만들기·설정, 감독 코드 — 2단계 6과 겹침
- [ ] 이메일 확인, 비밀번호 재설정 — 2단계 5와 겹침
- [ ] 코치진 관리(감독): 코치 코드 발급·해제
- [ ] 가입 코드 현황(감독): 선수별 본인·학부모 코드, 가입 여부, 만료일, 재발급
- [ ] 자녀 선택(학부모, 형제가 있을 때)
- [ ] 선수 삭제 → 보관(졸업·이적), 보관 선수 보기·복원
- [ ] 다가오는 일정 입력·수정·삭제
- [ ] 역할 5개에 맞춘 메뉴·권한 표시(감독 전용 버튼 등)
- [ ] 측정 입력·확인 화면 — 3번 결정에 따라 범위가 정해짐

**나중**
- [ ] 새 학년도 전환(3학년 일괄 졸업 보관, 학년 +1) — 시범 운영이 새 학년도를 넘기면 필수
- [ ] 내 계정(비밀번호 변경)
- [ ] 수정 기능: 피드백·훈련 일정·경기 수정, 측정 기록 수정·삭제
- [ ] 시즌별 기록 구분("2026" 고정 문구 제거)

**끝나는 기준:** 필수 항목이 모두 동작하고, 기능목록의 "없음"·"가짜" 중 필수 항목이 0.
