# SPTR

**야구선수의 측정 기록과 팀 운영을 연결하는 플랫폼**

중학교 야구부의 감독·코치가 선수의 신체·운동능력·실전 측정 기록을 입력하면 점수와 등급, 성장 추이, 훈련 우선순위가 계산되고, 같은 데이터가 출석·일정·경기 기록·라인업 같은 팀 운영 화면과 이어집니다. 선수와 학부모는 같은 데이터를 보기 전용으로 확인합니다.

- **체험 모드:** https://sptr-one.vercel.app → 로그인 화면의 **코치로 체험하기 / 선수로 체험하기** (가입 없이, 서버에 아무것도 올라가지 않음)
- 예시 팀 **배명중학교 야구부**의 선수 24명, 감독·코치, 측정값, 경기 기록, 출석은 **모두 지어낸 예시 데이터**입니다. 실제 인물과 관계없습니다. 측정값은 고정 시드 난수로 생성합니다(`src/lib/seed.ts`).

## 기능

| 기능 | 내용 |
|---|---|
| **측정 항목 34개** | 신체 11 · 운동능력 9 · 실전 5 · SBI/SMI 9. 모두 감독·코치가 입력하고 선수·학부모는 보기만 ([docs/측정항목.md](docs/측정항목.md)) |
| **점수 · 등급 계산** | 측정값을 항목별 기준 구간으로 0~100 정규화한 뒤 가중 합산 → 카테고리 점수와 종합 점수(GPE), S/A/B/C/D 등급, 약한 세부 항목 기준 훈련 우선순위 |
| **SBI / SMI 지표** | SBI(근력·버티컬·구속·스프린트 기반)와 SMI(제동력·가속 효율·팔꿈치 폄 기반), 최종 R = SBI/2 + SMI/2. 측정 이력과 팀 순위, 선수용 가상 계산기 |
| **경기 라인업** | 타순·수비 위치·지명타자, 측정·성적 기반 추천 자동 배치, 선수단 공개 |
| **팀 캘린더** | 월간 일정(연습경기·대회), 경기 결과를 입력하면 시합 기록과 연결, 월간 훈련 방향, 날짜별 훈련 공지와 선수 확인 현황 |
| **출석 관리** | 선수 본인이 출석·지각·결석을 체크하고 코치가 현황 확인·수정. 출석률 = (출석+지각) ÷ (기록한 날 − 사유결석) |
| 그 밖에 | 시합 기록(타격·투구, ⅓ 이닝 단위)과 부문별 랭킹, 선수단(학년·포지션 필터, 졸업·이적 보관), 코칭 피드백, 가입 코드(14일 만료, 1회용) |

## 점수 공식

```
GPE = 신체 × 35% + 운동능력 × 30% + 실전 × 35%
```

- 각 카테고리 점수는 세부 항목을 `norm(값, 최저 기준, 최고 기준)`으로 0~100 정규화한 뒤 가중 평균한 값입니다. 낮을수록 좋은 항목(대시 기록, 체지방률, 에러율)은 기준을 뒤집어 같은 함수로 처리합니다. 근력은 체중 대비 중량으로 봅니다.
- 등급: S ≥ 90, A ≥ 78, B ≥ 64, C ≥ 50, D < 50.
- **규칙 기반 계산입니다. 머신러닝·AI 예측이 아닙니다.** 모든 기준값과 가중치는 코드에 그대로 적혀 있고, 같은 입력이면 항상 같은 점수가 나옵니다. 기준은 U15(중학) 기준이며 근거 검증은 아직 진행 중입니다. 전체 공식과 코드 위치는 [docs/계산기준.md](docs/계산기준.md)에 있습니다.

## 구조

```
React 18 · TypeScript · Vite (Vercel 배포)
   │  화면은 메모리의 데이터를 먼저 고치고(낙관적 갱신)
   │  변경 전·후를 비교해 바뀐 행·칼럼만 서버 쓰기 작업으로 만든다
   ▼
Supabase Auth (이메일 로그인 + 가입 코드)
   │  RLS: 읽기 = 같은 팀, 쓰기 = 코치
   ▼
PostgreSQL (테이블 14개)
```

| 역할 | 읽기 | 쓰기 |
|---|---|---|
| 코치 | 우리 팀 전체 | 우리 팀 전체(측정·기록·일정·라인업·피드백·가입 코드) |
| 선수 본인 | 우리 팀 데이터(개인 피드백은 본인 것만) | 자기 출석 체크, 공지 읽음 표시 |
| 학부모 | 선수 본인과 같음 | 없음(보기 전용) |

- 권한은 앱이 아니라 DB의 RLS 정책이 막습니다. 졸업·이적으로 보관된 선수의 계정은 팀 데이터를 읽지 못합니다. 브라우저에는 공개용(publishable) 키만 있고 service_role 키는 쓰지 않습니다.
- **동기화:** 저장할 때 전체를 다시 쓰지 않고, 변경 전·후 메모리를 id로 비교해 새로 생겼거나 바뀐 행만 upsert, 이미 있는 선수는 바뀐 칼럼만 update 합니다. 쓰기는 순서대로 줄을 세워 보내고, 실패하면 그 변경과 뒤에 줄 선 변경을 화면에서 되돌린 뒤 서버에서 다시 읽습니다. 다른 기기의 변경은 창에 다시 들어올 때와 60초마다 반영합니다.
- **두 가지 모드:** 이메일 로그인은 서버 모드(Supabase), 체험하기는 브라우저 localStorage에만 저장하는 체험 모드입니다.

## 로컬 실행

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입 검사 + 프로덕션 빌드 (dist/)
```

환경 변수 없이 실행하면 데모용 Supabase 프로젝트에 연결됩니다(`src/lib/supabase.ts`). 체험 모드는 서버 없이 동작합니다.

### 내 Supabase 프로젝트로 실행

1. Supabase SQL Editor에서 `supabase/migrations/001_schema.sql` → `002_rls.sql` → `003_functions.sql` 순서로 실행합니다(여러 번 실행해도 됨, 지우려면 `supabase/rollback.sql`).
2. Authentication → Sign In / Providers → Email에서 **Confirm email을 끕니다**(켜 두면 가입 직후 세션이 없어 가입 코드 사용이 실패함).
3. `.env.example`을 `.env.local`로 복사하고 프로젝트 주소와 공개용 키를 넣습니다.

```bash
cp .env.example .env.local
```

## 아직 안 되는 것

- 이메일 확인(꺼 둠), 비밀번호 찾기
- 감독·야구부장·관리자 역할 구분(서버에는 코치·선수·학부모 세 가지). 팀은 가입한 누구나 만들 수 있음
- 실시간 구독(60초 주기 반영), 오프라인 저장. 같은 항목을 두 기기가 동시에 고치면 나중 저장이 남음
- 측정 센터 지도는 예시(가짜) 데이터

화면·동작별 상태는 [docs/기능목록.md](docs/기능목록.md)에 있습니다.
